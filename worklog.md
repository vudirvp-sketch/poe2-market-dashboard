- Read user-uploaded `тесты.txt` — found 6 pytest failures on Python 3.14.3 in `test_daily_stats_persistence.py::TestDailyStatsRoute` (all 6 tests in the class). Root cause: `asyncio.get_event_loop()` was deprecated since Python 3.10 and REMOVED in Python 3.14 — raises `RuntimeError: There is no current event loop in thread 'MainThread'` when called from a sync context with no running loop. The 12 call sites in the test file used `asyncio.get_event_loop().run_until_complete(coro)` to seed/close the HistoricalStore in sync test methods. On Python 3.12 these pass with a `DeprecationWarning`; on Python 3.14 they hard-fail.
- Verified the regression reproduces on Python 3.12 with the same code: `pytest tests/test_daily_stats_persistence.py::TestDailyStatsRoute` → 6 passed + 1 `DeprecationWarning: There is no current event loop` per test. Confirms the diagnosis.

- **Fix applied to `tests/test_daily_stats_persistence.py`:** (1) Added a module-level `_run(coro)` helper that calls `asyncio.run(coro)` — creates a fresh event loop per call. Safe for HistoricalStore because aiosqlite connections support cross-loop usage (each `await` binds the Future to the caller's loop; the aiosqlite worker thread posts results back via `loop.call_soon_threadsafe`). (2) Replaced all 12 `asyncio.get_event_loop().run_until_complete(...)` call sites with `_run(...)`: 3 patterns (`_run(store.init())`, `_run(store.close())`, `_run(_seed())`). The docstring reference to the old pattern is preserved in the `_run` helper's docstring for context. Test-only change — no production code touched.
