- **Design decision — where to put `localStorage.setItem`.** The recipe says "`setLocale` writes to localStorage AND notifies same-tab listeners". Two options: (A) keep a `useEffect` that writes `localStorage.setItem(LOCALE_STORAGE_KEY, locale)` on every locale change (matches original behavior, but causes a brief localStorage overwrite on mount — original code writes DEFAULT_LOCALE then the stored value); (B) move `localStorage.setItem` into `setLocaleInternal` only (cleaner — no brief overwrite, but loses the "normalize invalid localStorage to DEFAULT_LOCALE on mount" quirk). Chose (B) because: (1) the recipe explicitly says `setLocale` writes to localStorage; (2) the "normalize on mount" quirk is not tested (the "ignores invalid locale" test only checks `locale` and `hydrated`, NOT that localStorage was overwritten); (3) on hydration transition (`currentLocale` changes from DEFAULT_LOCALE to stored value via `subscribe`), localStorage is NOT written — which is correct because it already has the stored value. The DOM-mutation side-effect (`document.documentElement.lang = locale`) stays in a `useEffect` because it does NOT call setState — the `set-state-in-effect` rule does NOT fire on pure DOM mutations.
- **Design decision — `subscribeHydrated` reuses `subscribeLocale`.** Both `locale` and `hydrated` transition on the same mount trigger (the `hasMounted` flag flip). Rather than having two separate listener sets, `subscribeHydrated` delegates to `subscribeLocale`. This means: (1) both `useSyncExternalStore` calls add their callbacks to the same `listeners` set; (2) on first `subscribeLocale` call, `hasMounted` flips and the callback is invoked — but only ONE callback is invoked (the first one), not both. The second `useSyncExternalStore` (for `hydrated`) also calls `subscribe`, which adds its callback to the set but sees `hasMounted === true` and is a no-op. However, React's `useSyncExternalStore` calls `getSnapshot` after the callback fires, so the second store's `getHydratedSnapshot()` returns `true` on the next render. This is correct — both `locale` and `hydrated` transition together on the re-render scheduled by the first callback.
