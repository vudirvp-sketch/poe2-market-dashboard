Task: iter 122 — KI-24 `set-state-in-effect` 1 site resolved (`use-realms-and-leagues.ts`). Persistence-model redesign: the HIGH RISK site flagged in iter 121's stopping point. The effect's purpose was to (a) auto-select a default league when the async `leagues` list arrives AND (b) persist that selection to the Zustand store via `persistLeague`. The local `league` useState was initialized to `""` (NOT to the persisted `uiState.league`), so every reload triggered the auto-select effect and OVERWROTE the user's previously-persisted league with the API's auto-detected active league — a LATENT PERSISTENCE BUG. Fix: eliminate local `league` state, make `uiState.league` the single source of truth, add a "normalize" effect that calls Zustand `set` (NOT React `setState`, so the rule doesn't fire) to keep `uiState.league` valid for downstream hooks on other routes. Added 3 jest tests. Lint 118 → 117, 0 errors. 622 jest green, tsc green.

- **Confirmed the `set-state-in-effect` rule does NOT fire on Zustand `set`.** Inspected `dashboard-page.tsx` lint output: line 382 `setBaseCurrency(...)` (Zustand store action) is called inside a `useEffect` WITHOUT triggering the rule, while line 387 `setReferenceCurrency("")` (React `useState` setter) in the SAME effect DOES trigger. - **Confirmed `effectiveLeague` already handles the fallback.** The `useMemo` at line 117-121 derives: `if (league && leagues?.some(l => l.name === league)) return league;` → `const active = leagues?.find(l => l.active);` → `return active?.name || leagues?.[0]?.name || "";`. This is the CORRECT fallback (user selection > active > first) computed WITHOUT an effect. The auto-select effect's ONLY non-redundant purpose was persisting the auto-detected league to `uiState.league` (for downstream hooks on other routes: `use-currency-items.ts`, `use-unique-items.ts`, `use-exchange-pairs.ts` — all read `uiState.league` directly).
- **Design decision — eliminate local `league` state, use `uiState.league` as single source of truth.** Replaced `const [league, setLeagueLocal] = useState("")` with `const league = useDashboardStore((s) => s.uiState.league)` (selecting just the primitive to avoid re-renders on unrelated `uiState` changes). The `setLeague` wrapper now ONLY calls `persistLeague(newLeague)` — no local state. The `setRealm` wrapper calls `persistLeague("")` (clears persisted league; `effectiveLeague` re-derives for the new realm) instead of `setLeagueLocal("")`. The auto-select effect is REMOVED entirely — `effectiveLeague` handles the fallback. A "normalize" effect syncs `effectiveLeague` back into the store when the persisted league is invalid (empty or not in `leagues`), keeping downstream hooks on other routes supplied with a valid league. This effect calls `persistLeague` (Zustand `set`), NOT React `setState`, so the rule does NOT fire.
- **Design decision — guard against infinite loops in the normalize effect.** The condition `effectiveLeague !== league` (where `league` is read from the store) is false once the normalize runs (`persistLeague(effectiveLeague)` makes `uiState.league === effectiveLeague`), so no further calls. Traced the flow: (a) Initial: `uiState.league = "runes"`, `leagues = undefined` → effect no-ops (leagues empty). (b) Leagues arrive: `effectiveLeague = "Standard"` (because "runes" not in list) → effect fires: `persisted = "runes"`, `isValid = false`, `"Standard" !== "runes"` → `persistLeague("Standard")`. (c) `uiState.league = "Standard"`, re-render → `effectiveLeague = "Standard"` (because "Standard" IS in list) → effect fires: `persisted = "Standard"`, `isValid = true` → no `persistLeague`. ✅ No infinite loop.
