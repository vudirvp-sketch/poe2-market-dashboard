Refactored offline-banner.tsx: removed dead 'wasOffline' state (set
but never read) and replaced useEffect(() => { if (!isOnline)
setDismissed(false); }, [isOnline]) with the React-canonical 'adjust
state during render' pattern (previous-value guard). Eliminates 1
react-hooks/set-state-in-effect warning + 1 unused-var warning.

Recipe choice rationale: iter 115's signal-ref pattern requires a
useCallback consumer called synchronously from the same effect that
sets the ref. offline-banner.tsx has NO callback consumer — 'dismissed'
is consumed only in the render path (to derive showBanner). The
React-recommended pattern for 'reset state when a prop changes' with
no callback consumer is 'adjust state during render with a previous-
value guard' (https://react.dev/learn/you-might-not-need-an-effect#
adjusting-some-state-when-a-prop-changes). React supports setState
during render as a special case — it re-renders immediately without
committing the partial state, so there is no visual flash. The
react-hooks/set-state-in-effect rule does NOT fire because the
setState is NOT inside a useEffect.

prevIsOnline is initialized to the current isOnline value, so the
first render does NOT trigger a reset — important for hydration safety.

Semantics preserved (4-case trace verified):
- Online -> Offline: dismissed reset to false -> banner appears.
- User clicks dismiss while offline: dismissed = true -> banner hides.
- Offline -> Online: dismissed left as-is -> banner hidden (!isOnline
  is false).
- Online -> Offline (again): dismissed reset to false -> banner
  reappears.
